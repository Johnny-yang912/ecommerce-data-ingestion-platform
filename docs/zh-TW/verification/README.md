# 驗證記錄

[English](../../en/verification/README.md) | **繁體中文**

每一則記錄回答一個問題：**那個設計假設實際上成立嗎？** 它們寫一次就不再更新——那是「在量測的那一天量到了什麼」的記錄。

**這些不是單元測試。** 單元測試問的是*「這段程式碼對不對？」*；驗證記錄問的是*「這個**架構假設**對不對？」*——而且通常要刻意弄壞某個東西，在 CI 重現不了的規模上。

## 關於「推翻了東西嗎」這一欄

有六則記錄改變了一個已經被寫下來的結論。那一欄存在的理由是：**一個只能確認的驗證，價值不高**——價值在那些帶回不同答案的：

| 被推翻 | 原本 | 現在 |
|---|---|---|
| SIGKILL 恢復 | 「150 筆永遠卡住，重啟不會自動恢復」 | 零遺失——但光靠佇列做不到 |
| 逾時判定基準 | 假設 CAS 就夠了 | CAS 擋不住第三方把狀態退回去 |
| 限流 | `60/minute` | 靜默地變成 `60 × workers` |
| 有界掃描 | 假設批次發布是關鍵 | 它只有 1.1×——關鍵是分頁 |
| 分區過期 | 「超出範圍的日期會讓 build 失敗」 | 它們靜默落進 `__UNPARTITIONED__` |
| `--expect-rule-version` | 假設它抓得到版本分歧 | 它只比對自己行程內的版本 |

## 格式

```
## 驗證的假設    被測試的那個設計假設
## 環境          版本、資料量、在哪裡
## 方法          可複現的步驟
## 觀測          數字、表格、前後對比
## 結論          成立／不成立／有條件成立
## 這推翻了什麼  ⭐ 或「無」
## 相關          → ADR、設計文件
```
